# 环岛算法案例详解：bigandstone 与 MrSu18

> 整理日期：2026-10-24  
> 本文讨论两个公开工程的环岛思路，不展开逐行代码。  
> 重点：如何从“普通循迹”切换到“沿环岛虚拟路径行驶”，以及怎样让这个过程可重复。  
> 适用对象：当前使用 MT9V03X 二值图、逐行左右边界、中线误差、舵机 PD 和左右轮差速的循迹小车。

---

## 0. 先给结论

两个案例各有侧重：

| 案例 | 最值得学的内容 | 对你的价值 |
|---|---|---|
| bigandstone/SmartCar-Line-Following-RT1064 | 与当前硬件接近；用多类图像证据找环岛入口，再用 7 阶段流程和补线通过 | 最适合作为你现车的工程落地参考 |
| MrSu18/SmartCar-S18 | 单边巡线、逆透视、角点、编码器/陀螺仪共同控制状态推进 | 最适合学习“目标路径如何生成”和“状态机如何防止出错” |

两个案例的共同核心不是 PID，而是：

```text
先判断当前是不是环岛入口
-> 锁定环岛方向
-> 不再简单使用左右线中点
-> 用可见边线和赛道宽度生成虚拟中线
-> 用距离、角度或图像特征推进状态
-> 确认出环后恢复普通循迹
```

一句话概括：

> 环岛不是“把普通巡线误差调得更大”，而是“在一段时间内换一条目标路径”。

## 1. 你的入口为什么容易失败

`frame_0025.jpg` 中可以看到圆环外边界与主赛道在切点附近相连，中间有明显的蓝色圆洞。这个入口比典型的“丁字路口式环岛”更难，原因有三个。

### 1.1 白色区域在入口处合并

普通循迹假设：

```text
左边线 + 右边线 -> 取中点 -> 作为目标
```

环岛入口处，主赛道和环道可能连成一整块白色区域。此时左右边界虽然都存在，但它们不再表示“同一条道路的两侧”。

结果可能是：

- 中线落在主赛道和环道的中间；
- 中线看起来仍然连续，误差也不大；
- 控制器没有理由产生足够大的入环转角；
- 车继续沿直路或切向驶过，看起来像“没有识别到环岛”。

### 1.2 切向入口不一定出现明显丢线

很多环岛算法依赖“某一侧连续丢线”触发。但切向入口可能表现为：

- 赛道突然变宽；
- 一侧边界向外平滑展开；
- 前方出现蓝色圆洞；
- 同一行开始出现多个白色区间；
- 圆环外缘和主赛道外缘连成一条弧线。

这类入口可能没有几十行连续丢线，因此只靠丢线计数会漏检。

### 1.3 三行加权只能稳定横向误差，不能判断分支

当前三行加权解决的是“单个中线点噪声大”的问题，但三行都可能是错的：

- 三行都落在主赛道；
- 三行都落在环道；
- 近处落在主赛道，远处落在环道；
- 加权后得到一个物理上不存在的中点。

因此，感知层必须先回答“目标分支是谁”，控制层才有意义。

## 2. 案例一：bigandstone/SmartCar-Line-Following-RT1064

项目地址：

https://github.com/bigandstone/SmartCar-Line-Following-RT1064

它的硬件和软件结构与你最接近：

- RT1064；
- MT9V03X 摄像头；
- 二值化；
- 从图像底部向上的左右边线搜索；
- 舵机方向环；
- 编码器速度环；
- 左右轮差速；
- 环岛、十字、岔路、斑马线等元素处理。

### 2.1 整体图像流程

它的处理顺序可以概括为：

```text
摄像头图像
-> 自适应二值化
-> 去除小噪声
-> 从底部向上搜索左右边界
-> 元素识别
-> 元素专用处理
-> 中线平滑和加权偏差
-> 方向 PID
-> 速度环和差速
```

与你的代码相比，多出来的关键层是：

```text
Element_Test：我只判断当前是什么元素
Element_Handle：元素期间我怎样修改目标路径
```

这两个步骤分开很重要。

如果把“识别”和“控制”揉在同一个函数里，后面很难判断问题到底出在：

- 没有识别到入口；
- 识别到了但选错方向；
- 选对方向但补线不正确；
- 补线正确但舵机参数不合适。

### 2.2 环岛识别使用多类证据

它不只检查“是否丢线”，而是组合多个条件。

#### 证据一：赛道有效长度

如果边线太短、图像太乱，直接不做元素判断，避免在图像质量差时误触发。

#### 证据二：左右丢线数量是否明显不对称

左侧环岛候选通常表现为：

- 左边连续丢线较多；
- 右边基本完整；
- 右侧曲率还不大，说明车辆还没进入真正的大弯。

右侧环岛则相反。

这个条件的作用是快速缩小候选范围，但不能单独作为最终结论。

#### 证据三：边线曲率

代码用边线上近、中、远三个位置估算局部曲率。

环岛入口的圆弧会让一侧边线表现出持续、较稳定的弯曲趋势；普通直道或短噪声则不会。

曲率不是看某一个点，而是看一段边线的整体形状。这样可以减少单点跳变造成的误判。

#### 证据四：丢线边外侧的白点数量

这是它比简单丢线检测更关键的一步。

当一侧边线丢失后，程序会检查丢线位置外侧的一段区域中有多少白点。

- 如果是普通弯道，丢线边外侧通常很快变成蓝色背景；
- 如果是环岛，丢线处外侧仍可能存在连续的白色环道；
- 如果是斜十字，白点分布形态又会不同。

因此，“丢线 + 曲率 + 外侧白点”比单独任何一个条件都可靠。

#### 证据五：多行、多帧连续成立

入口判断不会依赖单帧。状态转移需要连续多行或连续多次满足条件。

这相当于带来两个效果：

- 降低图像噪声导致的误触发；
- 给车辆留出进入入口前的准备时间。

### 2.3 用“分带观察”判断入口形态

这是 bigandstone 案例中很值得学的思路。

它不会只看整个图像丢了多少行，而是把图像按距离分成几个横带：

```text
近处带
中近带
中远带
远处带
```

然后分别统计每一带的：

- 是否丢线；
- 丢线行数；
- 是否有线重新出现；
- 白段和黑段的变化顺序。

环岛入口在不同距离上会呈现特定的“丢线、恢复、再变化”顺序。通过分带判断，可以把它和普通弯道、十字、斜十字区分开。

这比“整张图丢线超过 30 行”更稳定，因为它保留了空间顺序。

### 2.4 七阶段状态机

它的环岛处理大致经历 7 个阶段：

| 阶段 | 目的 | 主要判断 |
|---|---|---|
| 1 | 检测入口起始形态 | 近处和中近处是否出现连续丢线 |
| 2 | 确认第一段入口特征 | 观察近处丢线、中远处是否仍有边线 |
| 3 | 确认第二段形态 | 检查中远处丢线或线形变化 |
| 4 | 拉线进环 | 用补线形成入环路径，同时累计行驶距离 |
| 5 | 环内行驶 | 用图像继续跟踪环道，准备识别出口 |
| 6 | 出环控制 | 检测出口并生成出环虚拟路径 |
| 7 | 结束确认 | 行驶一段距离后恢复普通循迹 |

这个结构最重要的不是“7”这个数字，而是三个设计原则：

1. **入口不是瞬间完成的。**  
   从看到入口到真正车辆进入环道，中间有距离，因此需要等待和确认。

2. **环内和出环使用不同的目标路径。**  
   入口阶段补入环线，环内阶段沿一侧边线，出口阶段再补出环线。

3. **距离是状态推进的物理约束。**  
   只靠图像时，车辆切内侧、看不到外环或短暂丢线都可能让状态卡住。编码器累计距离可以把状态向前推进。

### 2.5 补线是路径生成，不是“画一条装饰线”

在环岛阶段，它会利用：

- 当前稳定可见的一侧边界；
- 已知赛道宽度；
- 当前所处的入口/环内/出口阶段；
- 必要的固定偏移量；

来生成另一侧虚拟边界，然后计算目标中线。

对左环岛入环，常见做法是：

```text
可见的左边或右边边界
+ 赛道宽度
-> 虚拟另一侧边界
-> 虚拟中心线
```

这比在两段白色区域之间直接取中点更合理，因为虚拟边界带有明确的道路几何含义。

可以把补线理解为：

> 图像看不到完整道路时，用已知道路宽度和当前可见边缘，恢复出一条符合车辆运动的方向参考线。

### 2.6 元素期间的速度和转向

它的速度策略会给不同元素独立目标速度，环岛阶段通常明显低于直道。

这不是单纯为了安全，而是因为：

- 低速给图像判断多留几帧；
- 低速减小转弯半径误差；
- 差速过度时不容易把错误目标放大；
- 入口补线不完美时，车辆仍有修正余量。

转向方面，它会在元素期间限制舵机变化量，防止某一帧错误补线导致舵机瞬间打满。

### 2.7 这个案例的优点

- 与你的硬件平台最接近；
- 使用逐行扫描，不需要重写视觉架构；
- 识别证据丰富，不是只看单行；
- 状态机有明确的入口、环内、出口和结束；
- 用编码器距离避免状态永久卡死；
- 补线思路可以直接映射到 `LeftLine`、`RightLine`、`MidLine`。

### 2.8 这个案例的局限

- 没有声明开源许可证，适合学习，不建议直接复制发布；
- 阈值和赛道、摄像头安装高度、速度强相关；
- 编码器距离阈值不能跨车直接使用；
- 仓库里有旧版本备份、注释代码和多套重复逻辑，阅读时容易迷路；
- 环岛方向通常依赖比赛路线顺序或预设分支；
- 对特别平滑的切向入口，单靠丢线和曲率仍可能漏检。

### 2.9 从案例一应该带走什么

优先学习四个结构：

1. 元素识别与元素处理分离；
2. 丢线、曲率、白点数量、多行连续性共同判定；
3. 用可见边线加赛道宽度生成虚拟路径；
4. 用编码器距离推进状态并设置超时。

不要把具体阈值直接复制到你的车。它们只能作为标定方法的参考。

## 3. 案例二：MrSu18/SmartCar-S18

项目地址：

https://github.com/MrSu18/SmartCar-S18

这是第十八届智能车摄像头三轮组工程，MIT 许可证。

它最值得学习的不是某一个识别公式，而是整套“单边巡线 + 状态机 + 物理量约束”的设计。

### 3.1 与普通双边界巡线的根本区别

普通双边界巡线假设两侧都能看到：

```text
目标中心 = 左右边界的中间
```

环岛入口和环内经常只有一侧边界稳定可见，另一侧可能：

- 丢失；
- 属于另一条分支；
- 被车身遮住；
- 因透视和反光不可靠。

MrSu18 的思路是：

```text
先选择一条可信的边线
-> 根据赛道宽度生成另一侧
-> 再由单边边线计算目标轨迹
```

这就是“单边巡线”。

单边巡线的关键不是“只用一条线”，而是：

- 我知道自己跟的是左边还是右边；
- 我知道赛道宽度；
- 我能从这条线计算横向偏差和预瞄点；
- 我不需要依赖另一条可能错误的分支。

### 3.2 逆透视的作用

它的边线点会经过逆透视变换，从摄像头透视坐标转换到更接近俯视的道路坐标。

这样做的好处是：

- 远近位置的像素尺度更一致；
- 曲率和角度更接近真实道路形状；
- 预瞄距离可以按物理距离理解；
- 同一组曲率阈值不必因图像上下位置变化而大幅变化。

如果暂时不做逆透视，也可以在原图上做简化版本，但需要接受：

- 远处边线更敏感；
- 同样曲率在不同行上的像素斜率不同；
- 阈值更难统一。

对你的项目，逆透视不是第一步必需项。可以先保留行扫描，用“分带丢线 + 单边补线”跑通，再决定是否加入逆透视。

### 3.3 从边线到目标点

它不会直接把左右边线中点当作唯一目标，而是根据当前巡线类型选择：

- 跟左线；
- 跟右线；
- 跟特殊补线；
- 保持上一次偏差。

然后在边线上取一个预瞄点，计算它与车辆期望方向的偏差。

这带来一个重要能力：

> 在交汇区，程序可以明确决定“我现在跟的是哪一条边”，而不是让中点自然漂移。

### 3.4 环岛状态机

它的左右环岛分别有独立状态机，但结构对称。左环岛大致分为：

| 状态 | 含义 | 核心动作 |
|---|---|---|
| 0 | 检测环岛 | 找到入口证据后降速并标记环岛 |
| 1 | 等待入环时机 | 用编码器距离等待车辆走到真正入口 |
| 2 | 入环 | 选择单边边线，必要时重新扫线或生成补线 |
| 3 | 环内 | 跟外圆，寻找出口角点 |
| 4 | 出环 | 根据可见线生成出环路径 |
| 5 | 结束确认 | 确认恢复普通道路后退出状态机 |

状态之间的推进同时使用图像和物理量：

- 图像判断是否看到入口、角点和出口；
- 编码器判断已经走了多远；
- 陀螺仪角度判断是否已经转过足够大的圆弧。

### 3.5 为什么检测到入口后还要等待

从摄像头第一次看到入口，到车辆真正到达可转向位置，中间有一段距离。

如果检测到入口后立刻打舵，可能出现：

- 车辆提前切内；
- 转弯半径过小；
- 车辆压到环岛内侧；
- 入环后看不到外圆；
- 状态机误判已经出环。

MrSu18 用编码器累计距离等待入环时机。代码注释中给出的一个参考值是约 20 cm，但这个值必须按你的摄像头安装位置、速度和控制周期重新标定。

这体现了一个重要原则：

> 图像负责“看见”，距离负责“什么时候执行”。

### 3.6 入环阶段的单边补线

左环岛入环时，如果左边线大量丢失，程序会重新寻找左侧边线。

找到外侧圆环边缘后，它利用这条可见边线生成右侧虚拟边线和目标中心线。

如果左边线仍然可见，则继续沿左边线进入。

核心不是某一条固定规则，而是：

- 当前哪边更可信；
- 当前应该跟外圆还是内圆；
- 当前离入口的物理距离是多少；
- 当前是否已经进入稳定的圆弧段。

### 3.7 环内为什么默认跟外圆

环内如果两侧都试图使用，很容易出现：

- 内侧边界被圆洞遮挡；
- 外侧边界和出口分支混在一起；
- 左右边界来自不同圆弧；
- 中线在圆洞附近跳变。

跟外圆通常更稳定，因为外圆连续、曲率变化小，而且不容易被中心蓝色圆洞干扰。

当车辆切得太靠内、外圆看不到时，只靠图像会失去参考，所以还需要陀螺仪积分作为兜底。

### 3.8 出口检测

出口判断主要依赖：

- 边线曲率或角点；
- 边线从圆弧向直道过渡的趋势；
- 预瞄范围内出现明显折角；
- 图像和编码器/角度条件同时满足。

如果入口后车辆已经转过足够大的角度，但图像仍未找到出口，状态机会强制进入结束流程，避免车辆一直在环内。

### 3.9 出环阶段

出环时，程序根据左右线的可见情况选择策略：

- 左边线可见，跟左线出环；
- 右边线可见且角点位置合适，跟右线；
- 两边都丢失，使用最后一次可信位置生成虚拟直线；
- 如果角点太近但状态还需要继续，就保持上一帧偏差或固定转向，避免突然回中。

“保持上一次偏差”是元素控制中非常有用的技巧。

在补线不可靠时，突然把舵机回中通常比短暂保持原转向更危险。保持时间必须有限，并由超时机制兜底。

### 3.10 陀螺仪和编码器的分工

这两个传感器不是用来替代图像，而是解决图像无法判断的物理问题：

| 传感器 | 解决的问题 |
|---|---|
| 编码器 | 已走过多少距离，是否该从检测进入执行 |
| 陀螺仪 | 已转过多少角度，是否已经完成入环或该强制出环 |
| 图像 | 当前看到的是入口、圆弧还是出口 |

如果没有陀螺仪，可以先用：

- 编码器距离；
- 固定状态超时；
- 图像出口特征；

组成最小版本。

### 3.11 这个案例的优点

- 单边巡线适合环岛和分支场景；
- 状态层次清楚；
- 图像、编码器、陀螺仪职责明确；
- 有 PC 端 OpenCV 测试工程和实车图像；
- MIT 许可证，复用限制较少；
- 出环和异常退出有兜底；
- 对“补线失效后怎么办”考虑得比较完整。

### 3.12 这个案例的局限

- 初始环岛检测部分使用了电磁 ADC，不是纯视觉方案；
- 逆透视、重采样、角点检测增加实现和调参成本；
- 代码中仍有大量赛道专用阈值和注释分支；
- 平台是 TC264，不能直接搬到 RT1064；
- 单边巡线依赖赛道宽度和摄像头标定；
- 对普通弯道与环岛入口的视觉区分仍需要细致调参。

### 3.13 从案例二应该带走什么

优先学习四个思想：

1. 环岛期间从“双边界取中点”切换为“指定一条边线”；
2. 用可见边线加赛道宽度生成目标路径；
3. 图像判断类型，编码器/陀螺仪判断进度；
4. 补线不可靠时允许短暂保持上一偏差，但必须有超时。

## 5. 面向你当前代码的组合方案

### 5.1 感知层需要新增什么

当前代码主要只有：

- `EndRow`；
- `LeftLine[ROW]`；
- `RightLine[ROW]`；
- `MidLine[ROW]`；
- 三行方向误差。

建议增加四类状态信息：

1. 每一行左侧是否丢线；
2. 每一行右侧是否丢线；
3. 一侧连续丢线的起点和终点；
4. 当前选择的巡线类型。

巡线类型至少分为：

```text
双边界巡线
只跟左线
只跟右线
特殊补线
停止/恢复
```

这比只保存一个 `MidLine` 更能表达交汇区道路结构。

### 5.2 入口判断需要什么证据

建议至少使用两类证据，不要依赖单一条件。

基础证据：

- 一侧连续丢线；
- 另一侧保持稳定；
- 赛道宽度明显增大；
- 近处、中近、中远处丢线模式不同；
- 连续 3–5 帧成立。

增强证据：

- 前方出现稳定的蓝色圆洞；
- 一侧边线出现持续圆弧；
- 同一行出现两个以上白色区间；
- 分支方向和车辆当前航向一致。

对于 `frame_0025` 这种切向入口，建议把“赛道宽度增大”和“蓝色圆洞”放在较高优先级，因为单纯丢线可能不够明显。

### 5.3 目标路径怎样生成

普通模式：

```text
左边界和右边界都可信
-> 取中点作为目标
```

环岛模式：

```text
选择一条稳定边界
-> 根据赛道宽度生成另一条虚拟边界
-> 从虚拟边界计算目标中线
```

如果环岛方向已经确定，还需要保持方向锁定：

- 左环岛进入后不要因为单帧噪声切到右环岛逻辑；
- 出口前不要重新识别成新的环岛；
- 状态结束后设置短暂冷却时间。

### 5.4 状态机建议

最小可用状态：

| 状态 | 目的 |
|---|---|
| `NORMAL` | 普通双边界循迹 |
| `ROUND_DETECT` | 连续确认环岛入口 |
| `ROUND_APPROACH` | 锁定方向并等待真实入环位置 |
| `ROUND_ENTER` | 单边巡线、补线、强制入环 |
| `ROUND_ON_RING` | 沿环道稳定跟踪 |
| `ROUND_EXIT` | 生成出环路径 |
| `ROUND_END` | 确认恢复普通巡迹 |
| `RECOVERY` | 长时间无效时降速或停车 |

状态转移示例：

```text
NORMAL
  -> ROUND_DETECT：连续发现入口证据

ROUND_DETECT
  -> ROUND_APPROACH：入口证据稳定
  -> NORMAL：证据消失

ROUND_APPROACH
  -> ROUND_ENTER：距离/时间到达入环点

ROUND_ENTER
  -> ROUND_ON_RING：车辆已稳定进入圆弧
  -> RECOVERY：长时间没有有效边线

ROUND_ON_RING
  -> ROUND_EXIT：检测到出口
  -> ROUND_END：角度/距离超时

ROUND_EXIT
  -> ROUND_END：出环路径完成

ROUND_END
  -> NORMAL：赛道宽度和边界恢复稳定
```

### 5.5 控制层需要配合

环岛入口期间建议同时做三件事：

1. 降速；  
   可先从当前速度的 60%–75% 范围验证，不要直接沿用直道速度。

2. 限制差速；  
   错误分支出现时，过大的差速会和错误舵机输出叠加。

3. 限制舵机变化率；  
   某一帧补线错误时，不应让舵机瞬间打满。

方向微分低通和舵机变化率限制应该在环岛测试前完成，否则很难区分：

- 是入口目标错了；
- 还是目标正确但控制太猛。

### 5.6 安全与恢复

必须有至少一种超时机制：

- 入环后超过固定距离仍未进入稳定状态，降速；
- 环内超过固定距离仍未发现出口，强制出环；
- 长时间 `directionValid == 0`，进入恢复；
- 斑马线误触发 `StopFlag` 时记录原因，避免和环岛状态混淆。

如果没有陀螺仪，就先使用编码器距离和帧计数。不要因为缺少陀螺仪而不做状态机。

## 6. 最小版本和增强版本

### 6.1 最小可行版本

目标：先让车在 `frame_0025` 这类入口稳定转向，不追求高速。

建议只做：

```text
一侧连续丢线 + 赛道宽度增大
-> 锁定环岛方向
-> 降低速度
-> 选择稳定边线
-> 用赛道宽度补出虚拟中线
-> 编码器走过固定距离后进入环内
-> 检测出口或超时后恢复
```

这个版本不需要逆透视、不需要完整曲率识别，也不要求内环和外环同时可见。

### 6.2 增强版本

在最小版本稳定后，再增加：

- 逆透视；
- 边线重采样；
- 角点检测；
- 蓝色圆洞检测；
- 多白色区间匹配；
- 陀螺仪角度积分；
- 自适应阈值；
- 离线图像回放。

顺序不能反过来。感知目标不稳定时，加入更多曲率公式只会增加调试变量。

## 7. 调试时最应该记录什么

每帧至少记录：

- 当前状态；
- 左右边线是否有效；
- 左右连续丢线数量；
- 丢线起点和终点；
- 当前选择的巡线类型；
- 赛道路径是双边界还是单边补线；
- 最终目标中线；
- `directionError`；
- `ServoControlOut`；
- 左右轮目标速度和实际速度；
- 编码器累计距离；
- 是否触发环岛方向锁定；
- 是否触发超时或停车。

调试视频最好同时保存：

- 原始灰度图；
- 二值图；
- 左右边线叠加；
- 目标中线叠加；
- 当前状态文字；
- 当前舵机输出。

没有这些数据，只能从外部俯视视频推测，很难判断问题发生在哪一层。

## 8. 常见错误

### 8.1 只调大 Kp

入口目标本身错误时，增大 Kp 只会更快地冲向错误目标。

### 8.2 只看丢线数量

切向入口可能没有明显长时间丢线。必须同时看赛道宽度、圆洞、曲率和多白色区间。

### 8.3 在交汇区继续使用左右线中点

左右边界可能来自不同分支，中点没有物理意义。

### 8.4 补线和普通巡线共用同一套增益

补线容易出现跳变，入口阶段应当降速、限制差速并限制舵机变化率。

### 8.5 没有状态结束条件

只判断“进入环岛”而不判断“已经离开环岛”，车辆会在后续普通弯道继续使用环岛逻辑。

### 8.6 没有超时

摄像头丢线、反光、切内、外环不可见都可能让状态卡死。距离或时间超时必须存在。

### 8.7 直接复制参数

`38`、`40`、`20 cm`、`320°`、`30500` 这类数字都来自特定车辆和赛道，不能跨车照搬。

## 9. 推荐测试顺序

### 阶段一：离线回放

使用已经录制的车载二值图，逐帧标记：

- 环岛入口第一次出现；
- 应该锁定方向的帧；
- 应该开始补线的帧；
- 应该进入环内的帧；
- 出口第一次出现；
- 应该恢复普通循迹的帧。

如果离线视频都不能稳定标出这些事件，实车参数没有意义。

### 阶段二：低速入口

先把速度降到能稳定观察的水平，只测试入口：

- 是否锁定正确方向；
- 是否选对边线；
- 补线是否连续；
- 舵机是否出现突变。

### 阶段三：完整通过

入口稳定后再测试：

- 环内是否能保持；
- 出口是否能识别；
- 出环后是否恢复普通巡线；
- 是否重复触发环岛状态。

### 阶段四：重复性和提速

每个速度台阶至少重复多次，关注：

- 入口成功率；
- 正确分支率；
- 最大横向偏差；
- 舵机饱和比例；
- 状态卡死次数；
- 出环后重新误触发次数。

## 10. 最终建议

你当前最需要补的不是 PID 参数，而是三层结构：

```text
第一层：识别“这里不是普通弯，而是环岛入口”
第二层：决定“现在跟左边、右边，还是虚拟补线”
第三层：用距离/角度/超时决定“什么时候进入环内、什么时候出环”
```

bigandstone 适合学习第一层和第三层，尤其是：

- 多证据入口判断；
- 分带丢线；
- 七阶段状态；
- 编码器距离推进；
- 按阶段补线。

MrSu18 适合学习第二层，尤其是：

- 单边巡线；
- 逆透视后的角点和曲率；
- 可见边线加赛道宽度生成目标；
- 补线失效时保持上一偏差；
- 陀螺仪和编码器兜底。

建议先按最小可行版本实现，不要一开始同时加入逆透视、陀螺仪、内环识别和复杂曲率。先把“入口锁定方向 + 单边补线 + 距离超时”跑稳，再逐步增强。
